# Автоматизация тикетов поддержки

## Бизнес-гипотеза

Цель PoC — безопасно снять с операторов часть из 200 тысяч русскоязычных
тикетов в день, а не автоматизировать поддержку любой ценой. Если автоматически
закрывать 25% потока, система высвобождает до 50 тысяч ручных обработок, или
7,5 млн ₽ операторской ёмкости в день. Это становится денежной экономией только
при снижении аутсорсинговых затрат или обработке роста без дополнительного найма.

RabbitMQ защищает эту бизнес-ценность во время инцидентных всплесков: быстро
принимает большой поток тикетов и сохраняет backlog, пока LLM и операторы
обрабатывают его с безопасной скоростью. Это снижает риск потери обращений и
падения приёмного контура, помогает удержать SLA и не требует резервировать
дорогие LLM-мощности под редкие пики нагрузки.

North Star — число тикетов, закрытых без оператора при неизменных CSAT и reopen
rate. Guardrails: high-risk false negative = 0, auto-reply precision ≥ 98%,
Recall@3 ≥ 90%, p95 классификации < 500 мс. На текущем test: high-risk false
negative 0, auto-reply precision 100%, macro-F1 0,745 и p95 1,4 мс. Live
retrieval ещё должен подтвердить Recall@3 после запуска локальной модели.

## Решение

Адаптеры chat, email, web и mobile приводят вход к единому формату и маскируют
PII. Быстрый TF-IDF-классификатор определяет тему, после чего детерминированный
policy gate выбирает один из трёх маршрутов:

- `auto_reply` — автоматический grounded-ответ только для четырёх безопасных FAQ;
- `approve_require` — черновик ответа для проверки оператором;
- `human_need` — передача оператору без LLM для денежного риска, низкой
  уверенности или сбоя зависимости.

Hybrid-поиск Qdrant объединяет dense-векторы RuBERT Tiny 2 и sparse lexical
выдачу через RRF. FakeLLM или LiteLLM составляет ответ только на основе найденной
KB. Redis кэширует точные повторы, PostgreSQL хранит audit trail, Langfuse —
обезличенный trace. RabbitMQ отделяет быстрые классификацию и маршрутизацию от
более медленной генерации.

## Демонстрируемые сценарии

В Streamlit можно выбрать канал, устройство, пример и провайдера без ручного
ввода текста:

1. безопасный FAQ → поиск KB → `auto_reply`;
2. безопасный нестандартный вопрос → черновик → `approve_require`;
3. денежный риск или low-confidence → `human_need` без вызова LLM.

Повтор первого запроса показывает Redis cache hit. Для каждого решения видны
тема, confidence, маршрут, найденные документы и fallback reason.

## Быстрый запуск

Требования: Python 3.12+, uv и Docker Desktop. Embedding-модель работает на CPU.

~~~powershell
.\scripts\start.ps1
~~~

Скрипт проверяет `.env`, запускает пять Compose-проектов, ждёт готовности
сервисов, индексирует KB и открывает приложение на <http://localhost:8501>.
Первый запуск дольше обычного: Docker скачивает TEI и веса модели.

- интерфейс: <http://localhost:8501>;
- Langfuse: <http://localhost:3000>;
- Qdrant: <http://localhost:6335/dashboard>;
- RabbitMQ: <http://localhost:15673>;
- worker metrics: <http://localhost:9100/metrics>.

Query dataset оценивает уже построенную KB, но сам никогда не загружается в
Qdrant. `scripts/index_kb.py` индексирует 12 документов: dense-векторы RuBERT
Tiny 2 и sparse lexical-векторы для hybrid RRF.

Отдельный асинхронный контур можно показать командами:

~~~powershell
uv run python scripts/publish_ticket.py "Какие способы оплаты?" --provider fake
uv run python scripts/burst_test.py --count 20000 --provider fake
uv run python scripts/queue_metrics.py
~~~

Проверенный локальный burst: RabbitMQ подтвердил 20 000 из 20 000 сообщений за
88,1 секунды (`227 msg/s`), без publish reject и DLQ. После включения worker
контейнер остался healthy и начал контролируемо разбирать backlog.

## Проверка

~~~powershell
uv run pytest -q
uv run ruff check .
uv run python -m benchmark
uv run python -m benchmark --live --provider fake
~~~

Первый benchmark проверяет классификатор, risk gate и задержку без внешних
сервисов. Второй делает 60 запросов к реальным Qdrant и RuBERT Tiny 2 и считает
Hit@1, Recall@3, MRR, покрытие обязательных и появление запрещённых фактов.
LLM-as-a-judge не используется. Результаты пишутся в `benchmark/results/`.
Live retrieval-метрики не подменены фиктивными числами.

## Что реализовано, а что оставлено целевой архитектурой

Реализованы четыре входных адаптера, PII-маскирование, классификатор, policy,
hybrid retrieval, FakeLLM/LiteLLM, Redis, PostgreSQL audit, Langfuse, Streamlit,
RabbitMQ worker, retry/DLQ и Prometheus-метрики worker. Streamlit вызывает
pipeline синхронно, а RabbitMQ-контур демонстрируется отдельно.

Упрощения PoC: вместо настоящих интеграций каналов используется единый локальный
publisher; RabbitMQ и worker запущены в одном локальном Compose без HA и
autoscaling; нет incident clustering, полноценного DLP/RBAC и рабочего места
оператора. Эти части описаны как следующий шаг, а не как готовая production-система.
Очередь сглаживает легитимный burst, но не заменяет внешний WAF/rate limiting
для сетевого или HTTP DDoS.

## Экономика и пилот

Базовая стоимость: 200 000 × 150 ₽ = 30 млн ₽/день. Типовые обращения — 40%,
то есть верхняя граница автоматизируемого потока равна 80 тысячам тикетов и
12 млн ₽ операторской ёмкости в день.

| Сценарий | Auto-reply | Избежано ручных тикетов | Валовая ёмкость/день |
|---|---:|---:|---:|
| Теневой запуск | 0% | 0 | 0 ₽ |
| Консервативный пилот | 10% | 20 000 | 3,0 млн ₽ |
| Базовый | 25% | 50 000 | 7,5 млн ₽ |
| Верхняя граница типовых | 40% | 80 000 | 12,0 млн ₽ |

При допущении 0,20 ₽ за LLM-инференс базовый сценарий стоит около 10 тысяч
₽/день. Рост reopen rate на 1 п.п. среди 50 тысяч автоответов возвращает 500
тикетов, или 75 тысяч ₽/день. Раскатка: shadow mode → операторское подтверждение
черновиков → auto-reply только для FAQ, прошедших guardrails.

Ключевые допущения: 150 ₽ — средняя полная стоимость ручной обработки; 40%
тикетов действительно типовые; один тикет соответствует одной обработке;
высвобождённая ёмкость не равна немедленному сокращению расходов.

## Состав репозитория

- `data/query_dataset.jsonl` — 300 тикетов, 12 тем, ответы и ожидаемые действия;
- `kb/*.md` — 12 русских документов для hybrid-поиска Qdrant;
- `src/support_automation/` — адаптеры, классификатор, policy и pipeline;
- `streamlit_app.py` — UI с выбором канала, устройства, примера и провайдера;
- пять независимых Compose: приложение, embeddings, Qdrant, Langfuse и RabbitMQ.
