# ML и оценка качества

## Данные

`data/query_dataset.jsonl` содержит 300 русских тикетов: 12 тем по 25 примеров,
эталонный ответ, обязательные и запрещённые факты, ожидаемый документ, действие,
канал и устройство. 100 исходных формулировок взяты из CC0 Banking Requests,
остальные сгенерированы детерминированными шаблонами. Разбиение фиксировано:
180 train, 60 development, 60 test. Подробности — в [источнике
данных](../data/SOURCES.md).

Train обучает модель, development используется для выбора порога 0,22, test —
один раз для итогового отчёта. Тексты query dataset не индексируются в Qdrant:
в индекс попадают только 12 документов KB.

## Где правила, ML, retrieval и LLM

На горячем пути используется символьный TF-IDF (3–5-граммы) и Logistic
Regression. Это быстрый и воспроизводимый baseline без LLM. При явном денежном
сигнале классификатор может поднять high-risk тему из собственного Top-3; затем
отдельный детерминированный policy проверяет итоговую тему.

Policy, а не LLM, принимает решение:

- четыре узкие FAQ-темы → `auto_reply`;
- прочие безопасные темы → `approve_require`;
- денежный риск или confidence ниже 0,22 → `human_need` без LLM.

Для retrieval используются локальные dense-векторы
[RuBERT Tiny 2](https://huggingface.co/cointegrated/rubert-tiny2) и sparse
1–2-граммы `HashingVectorizer`; Qdrant объединяет результаты через RRF. Модель
русскоязычная, компактная (29,4 млн параметров, 312 измерений) и доступна по MIT.
Она выбрана вместо более тяжёлой BGE-M3, чтобы PoC воспроизводился локально на
CPU. Выбор считается подтверждённым только после live Recall@3 ≥ 0,90.

FakeLLM детерминированно проверяет связность pipeline и является baseline.
LiteLLM позволяет подключить реальную OpenAI-compatible модель. LLM не
классифицирует риск, не выбирает действие и не вызывается для `human_need`.

## Автоматическая оценка

- классификация: accuracy, macro-F1, Top-3 accuracy;
- безопасность: high-risk recall и false negative;
- policy: action accuracy и auto-reply precision;
- retrieval: Hit@1, Recall@3, MRR;
- ответ: покрытие обязательных фактов, forbidden fact rate, token-F1;
- производительность: p50/p95 классификации.

LLM-as-a-judge не используется: эталонные документы, обязательные/запрещённые
факты и действия дают быстрые детерминированные проверки. Критические пороги:
high-risk recall = 1, false negative = 0, auto-reply precision ≥ 0,98, p95 <
500 мс, live Recall@3 ≥ 0,90 и forbidden fact rate = 0.

## Текущий результат и ограничения

На 60 test-примерах: accuracy 0,75, macro-F1 0,745, Top-3 0,933,
high-risk recall 1,0, false negative 0, action accuracy 0,767, auto-reply
precision 1,0 и p95 классификации 1,4 мс. Невысокие accuracy и action accuracy
не скрываются: безопасность достигается консервативным human-in-the-loop, но
ценность автоматизации на реальном потоке ещё нужно доказать.

Live retrieval-результат намеренно не указан до запуска Qdrant и RuBERT.
Перед production нужны обезличенные реальные тикеты, двойная разметка спорных
тем, confusion matrix и shadow-пилот. По результатам пилота нужно откорректировать
границы принятия решения между `auto_reply`, `approve_require` и `human_need`.
Текущий confidence threshold 0,22 — значение только для PoC-выборки, а не
готовая production-настройка.

Новые границы выбираются на размеченных реальных тикетах отдельно по темам и
каналам. Сначала калибруется confidence, затем сравниваются precision/recall,
high-risk false negative, доля исправлений оператором, reopen rate, CSAT и
стоимость ручной обработки. `auto_reply` разрешается только в диапазоне, где
сохраняются safety-ограничения и ожидаемая экономия; промежуточные случаи идут в
`approve_require`, остальные — в `human_need`. Любой high-risk false negative
остаётся жёстким стоп-критерием независимо от экономического эффекта.
